# Contract evidence

Two files, generated by `npm run emit:samples`, and both are **evidence rather
than source**. Do not edit them by hand.

| File | What it is |
|---|---|
| `response-samples.json` | Real responses from the real controllers, over the real route table, against a migrated PostgreSQL. Not hand-written examples. |
| `route-table.json` | The route table Fastify actually registers. |

## Why they are recorded rather than written

A hand-written example states what someone believed the server returns, and it
agrees with the schema because the same person wrote both. These are the bytes.
A schema that disagrees with a sample here disagrees with what the server
actually sends — which is how three server divergences were found on the day the
arrangement was built, and three more the week after.

`route-table.json` exists because **declared and implemented are different
claims**. A path can be described in the OpenAPI document and reach nothing;
that was true of every client-facing endpoint for most of this project's life,
while the contract check happily reported that everything was declared.

## Why ids and timestamps are fixed

Every regeneration used to rewrite every id, timestamp and cursor, so a
meaningful change was one real line among eighty noisy ones — and a reviewer
learns to skim a file like that rather than read it.

`src/common/evidence/stabilise.ts` replaces them with fixed values, and the rule
that makes it safe is that **a value is only replaced if it is already valid**.
A malformed timestamp is left exactly as the server produced it, so it still
reaches the validator and still fails. Normalising indiscriminately would turn a
server bug into a passing gate, which is precisely what this whole arrangement
exists to prevent.

Two consecutive runs now produce a byte-identical file.

## Regenerating

```
npm run emit:samples
```

Writes into this directory. **Run it after any change to a response shape**, and
commit the diff — that diff is the record of what changed on the wire.

## Handing over to the contract repository

The contract repository validates these against its OpenAPI schemas and checks
both clients against the route table. That validation lives in that lane, not
this one, so it is a deliberate command rather than a side effect:

```
npm run emit:samples -- ../ebpco-contract/reconciliation
```

This used to be the **default**, which meant regenerating the backend's own
evidence silently edited a sibling repository owned by someone else. It is now
opt-in and explicit.
